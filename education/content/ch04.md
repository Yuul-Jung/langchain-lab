## 배경 개념: 왜 설정을 코드에서 분리하는가

제1~3장까지는 LM Studio 주소, 모델 ID, 인덱스 이름이 코드 곳곳에 직접 적혀 있었습니다. 다음 단계에서는 프로그램을 **VRAM 16GB AI PC**로 옮기고, 로컬 모델 외에 **대형 LLM API**(OpenAI·Anthropic 등)도 골라 쓰려고 합니다. 그때마다 코드를 고치면 실수가 생기고 테스트를 다시 해야 합니다.

그래서 바뀔 수 있는 값을 모두 `.env` 파일 하나로 모았습니다. 코드는 그대로 두고 `.env`만 바꿉니다.

| 바뀌는 상황 | 바꾸는 값 |
|---|---|
| 모델 서버를 AI PC로 옮김 | `LM_STUDIO_URL` |
| 다른 채팅 모델 사용 | `CHAT_MODEL` |
| 대형 LLM API 사용 | `OPENAI_API_KEY`·`OPENAI_MODEL` 또는 `ANTHROPIC_API_KEY`·`ANTHROPIC_MODEL` |
| 검색 인덱스 교체 | `ES_RAG_INDEX`, `ES_DOCUMENT_INDEX` |

**발견된 문제** — 분리 전에는 `.env`에서 Elasticsearch 값만 읽었습니다. `.env`에 `CHAT_MODEL`이나 `LM_STUDIO_URL`을 적어도 **조용히 무시**되고 코드의 고정값이 쓰였습니다. 이 장의 작업으로 모든 주소·모델·인덱스를 `.env`에서 읽게 고쳤습니다(2026-11-12).

## 전체 구조

```text
.env (GitHub에 올라가지 않음, 비밀번호·API 키 포함)
   ↓  settings.py  ── 값을 한곳에서 읽음: .env → 환경변수 → 기본값
   ├─ rag_search.py        ES 주소·인덱스·임베딩 모델
   ├─ document_pipeline.py  문서 인덱스·임베딩 차원
   ├─ local_status.py      공개 페이지 허용 출처
   └─ llm_providers.py     채팅 모델 제공자 선택
         ├─ local      LM Studio  (항상 사용 가능)
         ├─ openai     OpenAI 또는 호환 서비스  (키·모델 넣으면 사용 가능)
         └─ anthropic  Anthropic  (키·모델 + 추가 패키지)
   ↓
app.py  /api/models  → 채팅 화면의 "모델" 선택 목록 (키 없이)
        /api/chat    → 고른 제공자로 답변 생성
```

| 파일 | 역할 |
|---|---|
| `settings.py` | 설정 한곳 모음, 비밀값을 뺀 진단용 요약 `describe()` |
| `llm_providers.py` | 제공자 목록·사용 가능 여부·외부 전송 제한·LangChain 모델 생성 |
| `.env.example` | `.env`에 넣을 항목 안내 (실제 값 없음, GitHub 공개) |
| `tests/test_settings.py` 외 2개 | 서버 없이 도는 단위 테스트 |

## 설정을 읽는 순서

**파일** `settings.py` · 원본 발췌

```python
ROOT = Path(__file__).resolve().parent
ENV_FILE = ROOT / ".env"


def _load():
    return dotenv_values(ENV_FILE) if ENV_FILE.is_file() else {}


_VALUES = _load()


def get(name: str, default: str = "") -> str:
    """설정 하나 읽기 (.env → 환경변수 → 기본값)."""
    return _VALUES.get(name) or os.environ.get(name) or default


# ---- LM Studio (로컬 모델 서버)
LM_STUDIO_URL = get("LM_STUDIO_URL", "http://127.0.0.1:1234/v1")
CHAT_MODEL = get("CHAT_MODEL", "deepseek-r1-distill-qwen-14b")
EMBEDDING_MODEL = get("EMBEDDING_MODEL", "text-embedding-qwen3-embedding-4b")
# 인덱스 매핑과 반드시 같아야 한다. 바꾸면 기존 색인을 모두 다시 만들어야 한다.
EMBEDDING_DIMS = get_int("EMBEDDING_DIMS", 2560)
```

**코드 풀이**

- **`.env`를 환경변수보다 먼저** 봅니다. 제2장에서 실행 중인 프로세스에 남아 있던 예전 `ES_PASSWORD` 환경변수 때문에 401이 반복된 일이 있었습니다. 방금 저장한 `.env` 값이 예전 값에 덮이지 않게 하려는 것입니다.
- 기본값은 2026-11-12까지 코드에 고정되어 있던 값과 같습니다. `.env`에 아무것도 넣지 않으면 **동작이 전과 똑같습니다.**
- `EMBEDDING_DIMS`는 인덱스 매핑의 `dims`와 같아야 합니다. 임베딩 모델을 바꾸면 기존 색인을 모두 다시 만들어야 합니다.
- 설정은 **서버가 시작할 때 한 번** 읽습니다. `.env`를 고친 뒤에는 서비스를 재시작합니다.

```bash
# .env 를 고친 뒤 설정 반영
systemctl --user restart langchain-lab
```

## 모델 제공자 선택 구조

**파일** `llm_providers.py` · 원본 발췌

```python
def resolve(provider_id: str | None, mode: str, cfg=settings) -> Provider:
    """요청에 쓸 제공자를 고르고, 쓸 수 없으면 사용자에게 보여 줄 이유와 함께 ValueError."""
    pid = provider_id or cfg.DEFAULT_PROVIDER or "local"
    found = {p.id: p for p in providers(cfg)}
    if pid not in found:
        raise ValueError(f"설정에 없는 모델 제공자입니다: {pid}")
    p = found[pid]
    if not p.ready:
        raise ValueError(f"{p.label}을(를) 사용할 수 없습니다: {p.reason}")
    if p.external and mode == "rag" and not cfg.ALLOW_EXTERNAL_RAG:
        raise ValueError(f"문서 검색(RAG) 내용은 외부 API({p.label})로 보내지 않도록 설정되어 있습니다. "
                         "일반 채팅을 쓰거나 .env의 ALLOW_EXTERNAL_RAG를 확인하세요.")
    return p
```

```python
def make_chat(p: Provider, cfg=settings, temperature: float = 0, timeout: int = 180):
    """LangChain 채팅 모델 객체 생성. 세 제공자 모두 .invoke(messages) 로 같은 방식으로 호출된다."""
    if p.id == "local":
        from langchain_openai import ChatOpenAI
        return ChatOpenAI(model=p.model, base_url=cfg.LM_STUDIO_URL, api_key="lm-studio",
                          temperature=temperature, timeout=timeout, use_responses_api=False)
    if p.id == "openai":
        from langchain_openai import ChatOpenAI
        kwargs = {"model": p.model, "api_key": cfg.OPENAI_API_KEY,
                  "temperature": temperature, "timeout": timeout}
        if cfg.OPENAI_BASE_URL:
            kwargs["base_url"] = cfg.OPENAI_BASE_URL
        return ChatOpenAI(**kwargs)
    if p.id == "anthropic":
        from langchain_anthropic import ChatAnthropic
        return ChatAnthropic(model=p.model, api_key=cfg.ANTHROPIC_API_KEY,
                             temperature=temperature, timeout=timeout, max_tokens=4096)
    raise ValueError(f"알 수 없는 제공자: {p.id}")
```

**코드 풀이**

- 세 제공자 모두 LangChain 채팅 모델이라 `app.py`는 `llm.invoke(messages)` 한 가지 방식으로 호출합니다. 제1장의 프롬프트·한국어 재작성 규칙이 그대로 적용됩니다.
- **키와 모델 이름을 모두 넣은 제공자만** `ready`(사용 가능)입니다. Anthropic은 `langchain-anthropic` 패키지가 없으면 설치 명령을 이유로 보여 줍니다.
- 쓸 수 없는 제공자를 고르면 서버가 **400과 이유**를 돌려줍니다. 조용히 다른 모델로 바꿔 답하지 않습니다.
- 외부 API 오류 메시지에는 계정 정보가 섞일 수 있어, 화면에는 "API 키·모델 이름·네트워크·사용 한도를 확인하세요"만 보여 줍니다.

## 외부 API로 보내는 내용 보호

로컬 모델은 질문과 검색 근거가 내 PC 밖으로 나가지 않습니다. 외부 API를 고르면 **질문 내용이 그 회사 서버로 전송됩니다.**

| 모드 | 로컬 (LM Studio) | 외부 API (`ALLOW_EXTERNAL_RAG=false`, 기본) | 외부 API (`true`) |
|---|---|---|---|
| 일반 채팅 | 허용 | 허용 (화면에 전송 경고) | 허용 |
| RAG 채팅 (검색 근거 포함) | 허용 | **거절 (400)** | 허용 |

RAG 모드는 검색된 문장을 프롬프트에 넣습니다. 사내 자료나 과제 자료가 섞일 수 있으므로 기본값은 외부 전송 금지입니다. 채팅 화면은 외부 제공자를 고르면 "외부 API 모델입니다. 질문 내용이 해당 회사 서버로 전송됩니다."라는 문구를 표시합니다.

## 2026-11-12에 추가된 설정

같은 날 검색 품질 개선(제6장)과 업로드 한도 조정(제2장)을 하면서 설정이 늘었습니다. 모두 `.env`에서 바꾸고 서비스를 재시작하면 반영되며, 문서를 다시 색인할 필요는 없습니다.

| 설정 | 기본값 | 뜻 | 끄는 값 |
|---|---|---|---|
| `CHAT_RAG_SOURCE` | `documents` | 채팅 RAG가 검색할 곳: `documents`(업로드 문서) · `lab`(제1장 실습 문장) · `both` | — |
| `SEARCH_SCORE_MARGIN` | `0.05` | 1위 점수에서 이 폭 안의 결과만 보여 줌 | `0` |
| `SEARCH_TERM_WEIGHT` | `0.15` | 질문 낱말이 본문에 들어 있는 정도를 점수에 더하는 가중치 | `0` |
| `UPLOAD_MAX_MB` | `30` | 업로드 파일 크기 한도(MB) | — |
| `UPLOAD_MAX_SECTIONS` | `600` | 문서 하나의 절 수 한도 | — |
| `UPLOAD_MAX_CHUNKS` | `800` | 문서 하나의 청크 수 한도 | — |
| `CHAT_LIGHT_LEAK_FIX` | `true` | 채팅 답변에 한자 1자·일본어 가나 등이 조금 섞였을 때, 모델에게 한 번 고치게 하고 그 자리의 수정만 받아들임 (2026-11-13 추가, 제6장 문제 5) | `false` |

`SEARCH_TERM_WEIGHT=0`이면 낱말 재순위와 낱말 후보 검색이 모두 꺼져 벡터 검색만으로 순위를 매기던 때와 같은 순위가 됩니다(단위 테스트와 실제 채점으로 확인). `ALLOW_EXTERNAL_RAG=false`(기본)는 이제 업로드한 문서의 내용이 외부 API로 나가는 것을 실제로 막습니다.

**제한 사항** — 제공자별 답변 품질·속도·비용 비교는 아직 하지 않았습니다. RAG 채팅은 2026-11-12부터 업로드 문서를 검색합니다(제6장). 외부 API 제공자로 RAG를 쓰는 경로는 실제 API 키로 시험하지 않았습니다.

## 핵심 정리

- 주소·모델·인덱스·API 키는 `.env`에만 두고, 코드는 `settings.py`를 통해서만 읽습니다. `.env`가 환경변수보다 우선합니다.
- `.env`를 비워 두면 이전과 똑같이 로컬 DeepSeek으로 동작합니다.
- 채팅 모델은 로컬 / OpenAI(호환) / Anthropic 중에서 고르며, 키와 모델을 모두 넣은 제공자만 켜집니다.
- RAG 검색 근거는 기본적으로 외부 API로 보내지 않습니다.
- 다음 장에서는 공개 페이지에서 내 PC의 서비스를 시작·업데이트하고 상태를 확인하는 운영 구조를 다룹니다.
