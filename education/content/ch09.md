## 배경 개념: 개선했다고 믿기 전에 무엇을 확인하는가

제8장까지 한국어 부품 질문과 문서 검색을 여러 번 고쳤습니다. 고칠 때마다 점수가 올라 보였지만, 같은 질문을 보면서 고치면 그 질문에만 맞춘 개선이 되기 쉽습니다. 이 장은 **개선이 진짜인지 판정하는 절차**와, 그 절차로 판정한 결과를 기록합니다. 채택된 것뿐 아니라 **채택되지 않은 시도도 그대로** 적습니다.

절차의 핵심은 네 가지입니다.

```text
① 봉인 세트     개선하는 쪽이 보지 않은 질문 세트를 따로 쓴다 (숫자만 공유)
② 사전 등록     채택 기준을 실행 전에 적는다 (실행 뒤에 바꾸지 않음)
③ 한 번만 보기  봉인 세트는 개선 전 1회 + 개선 후 1회. 다 쓰면 은퇴
④ 후퇴 금지     다른 세트(보지 않은 것)에서 나빠지면 채택하지 않는다
```

두 Claude 세션이 역할을 나눴습니다. 한쪽이 개선을 만들고 자기 연습 세트로만 조정하면, 다른 쪽이 봉인 세트를 쓰고 판정합니다. 질문 내용은 넘기지 않고 숫자만 넘깁니다.

| 파일 | 역할 |
|---|---|
| `parts_gate.py` · `scripts/train-parts-gate.py` | 부품 관문의 보조 거부(학습 모델) |
| `part_conditions.py` | 여러 조건 질문의 조건 뽑기와 ✓·✗·? 판정 |
| `reranker.py` · `query_translate.py` | 문서 검색 재순위·질문 번역(둘 다 기본 꺼짐) |
| `scripts/ingest-folder.py` | 폴더의 문서를 서비스와 떨어진 평가용 인덱스에 넣기 |
| `scripts/eval-parts-ko.py` · `scripts/run-eval.py` | 부품 질문·문서 검색 채점 |

질문 세트·모델 파일·평가용 문서는 모두 `data/` 아래에 있어 GitHub에 올라가지 않습니다.

## 전체 흐름

```text
약점 발견 (봉인 세트에서)
   → 개선 담당: 일반 규칙 설계 → 자기 연습 세트로만 조정 → 기본 꺼짐으로 코드 준비
   → 판정 담당: 사전 등록(기준 숫자) → 같은 그래프·같은 설정으로 개선 전/후 1회씩
   → 기준 통과: 설정을 켜고 서버 재시작 / 미달: 꺼 둔 채 기록
   → 쓴 봉인 세트는 은퇴, 다음 회차는 새 봉인 세트
```

판정할 때는 개선 전 코드와 개선 후 코드를 **같은 그래프 파일 사본**으로 나란히 돌립니다. 개선 전 코드는 마지막 커밋을 임시 작업 폴더(git worktree)에 꺼내 씁니다.

```bash
# 개선 전(마지막 커밋) 코드를 임시 폴더로 꺼낸다 — 원래 작업 폴더는 그대로
git worktree add --detach /tmp/before HEAD
ln -s ~/langchain_web/data /tmp/before/data      # 평가 자료·카탈로그는 공유
ln -s ~/langchain_web/.env /tmp/before/.env
# … 두 폴더에서 같은 명령으로 채점 …
git worktree remove --force /tmp/before          # 끝나면 지운다
```

## 1단계: 학습 관문 — 부품 질문이 아닌 것을 한 번 더 거른다

부품 경로의 관문은 규칙(낱말·문법)으로 "부품 질문인가"를 정합니다. 낱말 규칙을 늘리는 2차 개선은 연습 세트에서만 좋아지고 봉인 세트에서는 효과가 없었습니다(채택 안 함). 그래서 방법을 바꿨습니다. **질문 임베딩으로 학습한 로지스틱 회귀**를 규칙 뒤에 붙이고, 확률이 아주 낮을 때만 되돌립니다.

```text
질문 → 규칙 관문 ─ 부품 질문 아님 → 기존 흐름 (모델을 부르지 않음)
              └ 부품 질문 → 학습 모델 P(부품) < 문턱 ? → 예: 기존 흐름 / 아니오: 부품 검색
```

문턱은 실행 전에 규칙으로 정했습니다. **5겹 교차검증에서 부품 질문의 가장 낮은 확률 − 0.02**입니다. 학습 자료에서는 부품 질문을 하나도 거부하지 않는 값입니다.

```python
# parts_gate.py (핵심 부분) — 실패하면 거부하지 않는다(원래 동작)
def veto(question: str, embed=None, path=None) -> bool:
    if not getattr(settings, "PARTS_GATE_ML", True):
        return False
    model = _load(path or MODEL)          # data/parts_gate/model.npz (w, b, tau)
    if model is None:
        return False
    try:
        return probability(question, embed or rag_search.embed_query, model) < model[2]
    except Exception:
        return False
```

```bash
# 은퇴한 질문 세트로 학습 (봉인 중인 세트는 넣지 않는다)
.venv/bin/python scripts/train-parts-gate.py --train data/eval/parts-ko-questions.jsonl data/eval/parts-ko-questions-71.jsonl ...
```

예상 출력:

```text
학습 460개(부품 273) · 교차검증 정확도 0.954 · 문턱 0.062 → 교차검증에서 거부: 부품 0 · 부품 아님 99/187
```

봉인 세트 10(부품 30·부품 아님 30)으로 판정했습니다.

| 지표 | 개선 전 | 개선 후 | 기준 |
|---|---|---|---|
| 부품 아닌 질문을 잘못 처리 | 5/30 | 3/30 | 줄어야 함 |
| 부품 질문 처리 | 26/30 | 26/30 | −1개까지 |
| 처리한 것 중 상위 5 적중 | 23/26 | 23/26 | 그대로 |

판정: **통과 → 켬**(`PARTS_GATE_ML`, 기본 켜짐). 끄려면 `.env`에 `PARTS_GATE_ML=false`를 넣고 재시작합니다.

## 2단계: 여러 조건 질문과 ✓·✗·? 표시

"SOT-23 패키지 3.3V LDO"처럼 조건이 둘 이상인 질문은 주 개념(LDO)만 맞혀서는 부족합니다. 질문에서 조건(인터페이스·전압·패키지·채널 수 등, 실행 전에 고정한 묶음)을 뽑고, 같은 후보 안에서 조건을 더 채운 부품을 앞으로 올립니다. 답에는 부품마다 조건 판정을 적습니다.

| 표시 | 뜻 |
|---|---|
| ✓ | 부품 이름·설명·키워드에 근거 낱말이 있음 |
| ✗ | 반대 값이 있음(예: 3.3V를 물었는데 5V 전용) |
| ? | 카탈로그에 적혀 있지 않아 확인할 수 없음 — ✓처럼 보이게 하지 않는다 |

카탈로그에 없는 정보(예: 마이크로컨트롤러의 핀별 대체 기능)는 확인할 수 없으므로 정직하게 `?`로 둡니다.

첫 판정에서는 여러 조건 세트에서 좋아졌지만, **단일 개념 질문 세트에서 적중이 줄어** 보류했습니다(23 → 20). 개선 담당이 원인(분류 순서·후보 수 변경)을 원래대로 맞춘 뒤, 새 봉인 세트로 다시 판정했습니다.

| 지표 | 꺼짐 | 켜짐 |
|---|---|---|
| 단일 개념 세트 11: 처리 / 적중 / 잘못 처리 | 29/30 · 28 · 2/15 | 29/30 · 28 · 2/15 |
| 여러 조건 세트: 모든 조건까지 맞춘 질문 | 21/22 | 21/22 |
| 여러 조건 세트: 상위 5개 중 조건까지 맞는 부품 비율 | 0.75 | 0.89 |
| 확인 불가 조건을 `?`로 표시 | 3/3 | 3/3 |

판정: **통과 → 켬**(`.env`의 `PARTS_CONDITIONS=true`). 기준을 숫자로 미리 적지 않은 첫 판정은 그 사실을 기록했고, 재판정은 숫자 기준을 먼저 적었습니다.

## 3단계: 실제 문서 — 데이터시트로 문서 검색 기준선

처음 올린 문서는 테스트용 샘플이었고, 사용자 요청으로 나중에 지웠습니다(정식 삭제 기능 추가). 실제 문서로는 KiCad 서비스에 맞는 **데이터시트**를 썼습니다.

- 사용자 PC의 데이터시트 폴더(읽을 수 있는 20개)
- KiCad 카탈로그 규칙(분류별 대표 부품의 제조사 공식 PDF 링크)으로 내려받은 것 중 쓸 수 있는 12개 — 사이트가 막은 것은 우회하지 않음

스캔 PDF(글자 없음)와 배포처가 복사 제한을 건 PDF는 처리하지 않았습니다(사용자 결정). 서비스와 섞이지 않게 별도 인덱스에 넣었습니다.

```bash
# 폴더 → 별도 인덱스·별도 보관함 (서비스 화면·기존 인덱스는 그대로)
.venv/bin/python scripts/ingest-folder.py --src ~/work_datasheets \
    --index langchain_datasheets_v1 --store data/datasheet_corpus --no-ai
```

한국어 질문 21개(원문 쪽을 직접 보고 확인한 사실만)로 잰 첫 기준선입니다.

| 지표 | 값 |
|---|---|
| 맞는 문서를 1위로 | 0.905 |
| 맞는 쪽을 1위로 | 0.476 |
| 맞는 쪽이 상위 5 안 | 0.81 |

맞는 문서는 거의 찾지만 **맞는 쪽을 1위로 올리지 못하는 것**이 약점입니다. 질문은 한국어, 문서는 영어이기 때문입니다. 한국어 분석기(노리)는 영어 문서에 효과가 없어 순위가 하나도 바뀌지 않았습니다(채택 안 함).

## 4단계: 채택되지 않은 시도

| 시도 | 연습 세트 | 봉인 판정 | 결과 |
|---|---|---|---|
| 낱말 규칙 추가(일반 질문 거르기 2차) | 좋아짐 | 봉인 세트 3개 모두 변화 없음 | 미채택 |
| 한국어 낱말 → 영어 덧붙이기(고정 낱말 표) | 변화 없음 | 보지 않음(아껴 둠) | 되돌림 |
| 재순위 모델(교차 인코더) | 1위 적중 크게 오름 | 1위 +1문항(기준 +2), 상위 5 하락, 한국어 문서 후퇴 | 미채택 |
| 질문 번역 dual | 조금 오름 | 영어 문서는 좋아짐, 한국어 문서 1문항 후퇴 | 미채택 |
| 질문 번역 auto(결과가 영어일 때만) | dual과 같음 | 한·영 섞인 인덱스에서 영어 질문 MRR 하락 | 미채택 |

두 가지 교훈이 있습니다. 첫째, **연습 세트에서의 큰 개선이 봉인 세트에서는 사라지는 일이 흔합니다.** 둘째, 문서가 한 종류일 때와 **섞였을 때** 결과가 다릅니다. 영어 데이터시트만 있던 연습에서는 안 보이던 후퇴가 한국어 문서와 섞자 나타났습니다. 번역은 연습 자료를 더 모은 뒤 다시 시도합니다.

## 5단계: 실제 사용자 질문을 모으는 장치

봉인 세트도 결국 우리가 쓴 질문입니다. 다음 판정 재료는 **실제 사용자 질문**이어야 합니다. 질문을 지어내지 않기 위해 다음을 만들었습니다.

- 부품 답 아래 버튼: 맞음 / 부품 질문 아님 / 다른 부품을 원함
- 다른 답 아래 버튼: 부품을 물었는데 못 알아들음
- 예시 질문을 자동으로 보내는 버튼은 두지 않음(기록이 오염되므로)
- 처음 들어오는 실제 질문 30개(또는 평가 10개)는 봉인해 개선 전 1회 측정에만 쓴다(사전 등록)

기록은 이 PC에만 남고, 질문 원문은 공유하거나 커밋하지 않습니다.

| `PARTS_GATE_ML` | true | 켜짐 | 학습 관문(모델 파일이 없으면 원래 동작) |
| `PARTS_CONDITIONS` | false | 켜짐 | 여러 조건 질문 정렬과 ✓·✗·? 표시 |

| 학습 관문 봉인 판정 | 통과 |
| 여러 조건 재판정 | 통과 |

- 봉인 세트도 두 세션이 쓴 초안이며 사람이 검토하지 않았습니다. 세트 크기는 15~60문항으로 작아, 한 문항이 지표를 크게 움직입니다.
- 판정자는 개선 규칙의 설명을 들은 상태에서 봉인 세트를 썼습니다(독립성 한계, 각 세트 머리말에 기록).
- 데이터시트 질문은 대부분 표지·첫 쪽 사실이라, 깊은 쪽의 검색 성능은 덜 확인되었습니다.

## 핵심 정리

1. 개선은 그것을 만든 쪽이 보지 않은 봉인 세트로, 미리 적은 기준으로, 한 번만 판정한다.
2. 연습 세트에서 좋아진 것이 봉인 세트에서 사라지면 채택하지 않고 그대로 기록한다.
3. 낱말 규칙이 한계에 닿으면 방법을 바꾼다(학습 모델은 규칙 뒤의 보조 거부로만).
4. 확인할 수 없는 조건은 `?`로 정직하게 보여 준다.
5. 문서가 섞이면 결과가 달라진다 — 판정 자료는 실제 서비스와 같은 구성으로 만든다.
6. 다음 판정의 재료는 지어낸 질문이 아니라 실제 사용 기록이다.
