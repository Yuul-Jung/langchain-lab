## 배경 개념과 설계 원칙

제2장의 문서 파이프라인은 `pypdf`로 PDF의 텍스트 레이어를 읽습니다. 그래서 **스캔 PDF, 슬라이드를 이미지로 저장한 PDF, 화면 캡처가 들어간 페이지**에서는 텍스트가 비거나 일부만 나옵니다. 제3장은 이런 페이지를 이미지로 바꿔 두 가지 방식으로 읽고 결과를 대조합니다.

- **OCR(Optical Character Recognition, 광학 문자 인식)** — Tesseract가 글자를 그대로 옮깁니다.
- **VLM(Vision-Language Model, 시각 언어 모델)** — Qwen3-VL이 화면을 이해해 주제·항목·흐름을 요약합니다.

```text
① PDF 페이지          텍스트 레이어가 없거나 불완전
      ↓
② 300dpi PNG          A4 기준 2481 × 3508 픽셀
      ↓
      ├─▶ ③-a Tesseract OCR        psm3 · psm6, 글자를 그대로 옮김
      └─▶ ③-b Qwen3-VL (LM Studio)  주제·항목·흐름 요약, verified: false
      ↓
④ 식별자 대조          클래스명 · 모델명 · 약어 일치 여부
      ↓
⑤ 사람 검토            '의심' 항목만 원본 이미지로 확인
```

**기본 원칙** — VLM 요약은 원문이 아니라 **해석**입니다. 결과는 `verified: false`로 저장하고, OCR 원문과 원본 이미지로 확인하기 전까지 검색 색인이나 교재 원문으로 쓰지 않습니다. 대조 스크립트는 읽기 전용입니다.

| 파일 | 역할 |
|---|---|
| `vlm_ocr.py` | 이미지 → base64 요청, LM Studio 오류 해석, 식별자 추출·대조 (표준 라이브러리만 사용) |
| `scripts/vlm-analyze-pages.py` | 페이지 번호를 받아 VLM 요약 JSON 저장 |
| `scripts/compare-ocr-vlm.py` | VLM 요약과 OCR 원문의 식별자 대조 보고서 생성 |
| `tests/test_vlm_ocr.py` | LM Studio 없이 도는 오프라인 테스트 11개 |

## VLM 요청 형식

**파일** `vlm_ocr.py` · 원본 발췌 · 오프라인 테스트 통과

```python
def build_payload(image_uri: str, *, model: str = DEFAULT_MODEL,
                  prompt: str = DEFAULT_PROMPT, max_tokens: int = 2048,
                  temperature: float = 0.1) -> dict:
    if not image_uri.startswith("data:image/"):
        # file:// 나 http:// 를 넘기면 LM Studio가 400으로 거부한다.
        raise ValueError("image_uri는 data:image/...;base64, 형식이어야 합니다")
    return {
        "model": model,
        "temperature": temperature,
        "max_tokens": max_tokens,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": prompt},
            {"type": "image_url", "image_url": {"url": image_uri}},
        ]}],
    }
```

**코드 풀이**

- OpenAI 호환 형식의 `image_url`을 쓰지만 LM Studio는 **파일 경로나 웹 주소를 받지 않습니다.** `file://`을 넘기면 `'url' field must be a base64 encoded image.`로 거부됩니다. 이 함수는 그런 요청을 보내기 전에 막습니다.
- `image_data_uri()`가 PNG 파일을 `data:image/png;base64,…` 문자열로 바꿉니다.
- `temperature 0.1` — 같은 페이지를 다시 돌려도 결과가 크게 달라지지 않게 낮춥니다.
- 응답의 `finish_reason`이 `stop`이면 정상 종료, `length`면 `max_tokens`에서 답변이 잘린 것입니다. 결과 JSON에 함께 저장합니다.

## HTTP 400 진단 기록

처음 실행에서는 `HTTP Error 400: Bad Request`만 출력되고 원인이 보이지 않았습니다. 아래는 실제로 원인을 찾아간 순서입니다. **교훈은 하나입니다: 오류 응답의 본문을 반드시 출력합니다.**

```text
① 모델 목록              GET /v1/models → id 확인
      ↓
② 텍스트만 요청          서버·모델 ID 정상 여부
      ↓
③ 정상 작은 이미지       이미지 형식 자체가 통하는지
      ↓
④ 실제 페이지 + 짧은 질문  이미지 크기 문제인지
      ↓
⑤ 실제 스크립트 + 오류 본문 출력  남은 차이를 서버가 직접 설명
```

| 단계 | 시도 | LM Studio 응답 | 결론 |
|---|---|---|---|
| ① | `/v1/models` | `qwen3-vl-4b` 있음 | 모델 ID 정상 |
| ② | 텍스트만 | 200 | 서버·모델 정상 |
| ③-a | 손으로 적은 1×1 PNG 바이트 | `Failed to load image or audio file` | **테스트용 PNG가 깨져 있었음** — 서버 문제 아님 |
| ③-b | `file://` 경로 | `'url' field must be a base64 encoded image.` | base64만 받음 |
| ③-c | zlib로 만든 정상 8×8 PNG | 200 | base64 형식 정상 |
| ④ | 실제 2481×3508 페이지 + 짧은 질문, `max_tokens` 60 | 200 | 이미지 크기 자체는 문제 아님 |
| ⑤ | 원래 스크립트(긴 질문, `max_tokens` 2048) | `request (4100 tokens) exceeds the available context size (4096 tokens)` | **원인: 컨텍스트 4096 초과** |

**파일** `vlm_ocr.py` · 원본 발췌

```python
try:
    with urllib.request.urlopen(req, timeout=timeout) as resp:
        data = json.loads(resp.read().decode("utf-8"))
except urllib.error.HTTPError as exc:
    # 본문을 반드시 읽어야 원인이 보인다. "400 Bad Request"만으로는 진단할 수 없다.
    body = exc.read().decode("utf-8", errors="replace")
    raise RuntimeError(f"HTTP {exc.code}: {body[:400]}\n→ {explain_http_error(body)}") from None
except urllib.error.URLError as exc:
    raise RuntimeError(f"LM Studio 연결 실패: {exc.reason} → lms server status 확인") from None
```

**코드 풀이** — `HTTPError`는 `URLError`의 하위 클래스입니다. 처음 스크립트는 `except URLError`만 있어서 400 응답을 "연결 실패"로 출력하고 본문을 버렸습니다. `HTTPError`를 먼저 잡아 `exc.read()`를 출력하면 LM Studio가 보낸 구체적인 이유가 나옵니다. `explain_http_error()`는 위 표의 응답 문구를 조치 안내로 바꿔 덧붙입니다.

**③-a에서 배운 것** — 진단용 테스트 데이터가 틀리면 진단 전체가 엉뚱한 방향으로 갑니다. 테스트 이미지는 손으로 바이트를 적지 말고 코드로 만든 뒤 이미지 라이브러리로 열리는지 먼저 확인합니다. `tests/test_vlm_ocr.py`의 `tiny_png()`가 그 방법입니다.

## OCR ↔ VLM 식별자 대조

```bash
.venv/bin/python scripts/compare-ocr-vlm.py 115 116 117
cat ~/pdf_recovery_work/vlm_result/compare_ocr_vlm.md
```

실측 데이터를 현재 판정 규칙으로 계산한 요약:

```text
[115] VLM 식별자 22개 — 확인 22, 의심 0 / VLM 누락 후보 4개
[116] VLM 식별자 14개 — 확인 10, 의심 4 / VLM 누락 후보 0개
[117] VLM 식별자 7개 — 확인 4, 의심 3 / VLM 누락 후보 0개
```

| 판정 | 기준 |
|---|---|
| 일치 | 공백·기호·대소문자를 무시하고 OCR 원문에 그대로 있음 |
| 유사 | 길이가 거의 같고 유사도 0.8 이상인 OCR 단어가 있음 → OCR 오독 가능성. 예: `QuestionAnswerAdvisor` ↔ `QuestionAnswerAdvisar` |
| 없음 → 의심 | 어느 OCR에도 없음 → VLM이 덧붙였거나 OCR이 놓침. 원본 이미지로 확인할 대상 |

**파일** `vlm_ocr.py` · 원본 발췌

```python
def best_similar(term: str, candidates, threshold: float = 0.8):
    """길이가 거의 같은 후보 중 가장 비슷한 것. 'PgVectorStore'와 'VectorStore'처럼
    한쪽이 다른 쪽을 포함하는 경우는 오타가 아니므로 길이 조건으로 걸러낸다."""
    n = norm(term)
    allow = max(1, round(len(n) * 0.1))
    best, best_r = None, 0.0
    for cand in candidates:
        c = norm(cand)
        if not c or abs(len(c) - len(n)) > allow:
            continue
        r = SequenceMatcher(None, n, c).ratio()
        if r > best_r:
            best, best_r = cand, r
    return (best, best_r) if best_r >= threshold else (None, 0.0)
```

**코드 풀이**

- **길이 필터** — `PgVectorStore`와 `VectorStore`의 유사도는 0.92지만 오타가 아니라 다른 이름입니다. 길이 차이가 10%를 넘는 후보는 빼서 이런 오판을 막습니다.
- **누락 후보 필터** — OCR의 `OpenAl`은 VLM의 `OpenAI`를 잘못 읽은 것이므로 "VLM이 빠뜨린 것"으로 세지 않습니다. 첫 버전은 이 필터가 없어 115쪽 5개, 116쪽 2개로 나왔고, 그중 `OpenAl`, `gpt-40-mini`가 OCR 오독이었습니다.
- 한글 문장은 비교하지 않습니다. OCR 품질 편차가 커서 영문 식별자만 대조합니다.

## 결과 해석: 서로의 약점

3쪽을 대조한 결과, 두 방식은 **틀리는 곳이 서로 다릅니다.**

| 항목 | 더 정확한 쪽 | 관찰된 예 |
|---|---|---|
| 영문 식별자·모델명 | VLM | OCR은 대문자 I를 l로(`OpenAI`→`OpenAl`, `AI`→`Al`), 소문자 o를 0으로(`gpt-4o-mini`→`gpt-40-mini`), `Top-10`→`100-10`처럼 반복해서 잘못 읽음 |
| 한글 문장 | OCR | VLM은 단어를 비슷한 말로 바꿈 (쿼리→퀴리, 전체→전제, 잘림→잃어지고) |
| 빠짐없이 담기 | OCR | VLM은 실행 로그 화면, 안내 문구 같은 부수 영역을 요약에서 빠뜨림 |
| 도형 속 번호·기호 | 둘 다 부족 | OCR은 ①②를 `©`, `@`, `(01:`로 깨뜨리고, VLM은 요약하며 재구성함 |
| 의미 해석 | 주의 | VLM이 "도입 권장 순서"를 "질문이 처리되는 실행 흐름"처럼 설명함 |

**결론** — **OCR 텍스트를 바탕으로 두고, 영문 식별자만 VLM 표기로 고치는 방식**이 원문에 가장 가깝습니다. VLM 요약을 원문 대신 색인하면 한글 표현이 바뀌고 일부 내용이 사라집니다. 반대로 OCR 텍스트를 그대로 색인하면 "OpenAI", "gpt-4o-mini" 같은 키워드 검색에 걸리지 않습니다.

'의심'으로 나온 `RAG`, `LLM`, `PDF`, `DB`는 VLM이 설명하면서 덧붙인 일반 약어였습니다. '의심'은 "확인 필요"라는 뜻이지 곧 오류라는 뜻이 아닙니다.

## 터미널 붙여넣기 깨짐

실습 중 30줄이 넘는 `cat > file <<'PY' … PY` 블록을 터미널에 붙여넣다가 줄이 뒤섞이고, 프롬프트가 `>`에서 멈추는 일이 두 번 있었습니다. 파일은 저장되지 않거나 일부만 저장됩니다.

| 상황 | 조치 |
|---|---|
| 프롬프트가 `>`에서 멈춤 | Ctrl+C로 빠져나온 뒤 `ls -l`로 파일이 생겼는지 확인하고, 깨진 파일은 지움 |
| 긴 스크립트를 옮겨야 함 | **저장소에 넣고 `git pull`로 받음** — 이 장의 스크립트를 저장소에 둔 이유 |
| 저장소 밖 임시 스크립트 | gzip+base64로 압축한 **한 줄** 명령으로 옮김. 한 글자라도 깨지면 `gunzip`이 실패해 깨진 파일이 실행되지 않음 |

```bash
# 보내는 쪽
gzip -9c script.py | base64 -w0

# 받는 쪽 (한 줄)
echo 'H4sI…' | base64 -d | gunzip > script.py && python3 -m py_compile script.py
```

## 검증 결과와 제한

| 항목 | 근거 | 판정 |
|---|---|---|
| base64 이미지 요청 | 정상 PNG·실제 페이지 200 응답 | 통과 |
| 컨텍스트 16384 로드 후 3쪽 분석 | 14~16초, `finish_reason: stop` | 통과 |
| 식별자 대조 (3쪽) | 보고서 생성, 의심 항목 원문 확인 | 통과 |
| `vlm_ocr.py` 오프라인 테스트 | 11개 통과, 가짜 서버로 400 안내 출력 확인 | 통과 |
| `vlm-analyze-pages.py` 실제 LM Studio 실행 | 실행 기록 없음 | 미검증 |
| 페이지 이미지·OCR 생성 명령 | 참고 명령, 이 교재 환경에서 미실행 | 미검증 |
| OCR 식별자 자동 보정 | 설계만 있음 | 미구현 |

**제한 사항**

- 실측은 슬라이드형 강의자료 3쪽입니다. 표·수식·손글씨 페이지에서는 결과가 다를 수 있습니다.
- 영문 식별자만 대조하며, 한글 문장의 정확도는 자동으로 판정하지 않습니다.
- 4B 모델은 흐름은 잘 잡지만 용어를 바꾸거나 해석을 덧붙입니다.
- 노트북 GPU 기준 한 쪽에 약 15초입니다. 수백 쪽이면 일괄 작업 시간을 따로 잡아야 합니다.
- 페이지 이미지, OCR 텍스트, VLM 요약은 원본 자료에서 나온 것이므로 저장소에 커밋하지 않습니다.

## 핵심 정리

- LM Studio 비전 모델에는 이미지를 `data:image/png;base64,…`로 보냅니다. `file://`은 거부됩니다.
- 300dpi 페이지 한 장 ≈ 4,000 토큰. 모델은 **컨텍스트 16384**로 로드합니다.
- HTTP 오류는 본문을 출력해야 원인이 보입니다. 진단용 테스트 데이터부터 검증합니다.
- OCR은 한글과 빠짐없는 내용에, VLM은 영문 식별자에 강합니다. 둘을 대조해 씁니다.
- VLM 결과는 `verified: false`이며, 의심 항목만 사람이 원본 이미지로 확인합니다.
