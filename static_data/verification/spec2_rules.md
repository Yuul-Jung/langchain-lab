# 명세 2 규칙 문장 (오라클의 근거, 2판, jung-f1 작성 · 98 검토 6건 반영, 엔진 코드 미열람, 위임)

오라클(`verification/oracle_constraints.py`, 아직 없음)은 이 문장만으로 쓴다. 엔진(`constraints.py`)은 열지 않는다. 엔진과 어긋나면 이 문장으로 판정한다(문장이 틀렸다면 문장을 고치고 이유를 기록, 결과에 맞춰 바꾸지 않는다). 근거가 약한 문장은 "근거 약함"으로 표시했다.

## 입력
사례 = 필드 5개(supply_min_v·supply_max_v·abs_max_supply_v·temp_min_c·temp_max_c)별 값 목록(각 값은 출처 단계와 숫자) + 동작점(전원 전압 V, 주변 온도 **구간** [Ta_lo, Ta_hi]). 값 목록은 비어 있을 수 있다. 출처 단계는 사람 확인·위임 확인·데이터시트·유통사·라이브러리뿐이다(자동 추출 'extracted' 값은 입력에 없다. 들어오면 입력 오류).

## 입력 검증 (R0)
- 동작점의 V 가 없거나 Ta_lo > Ta_hi 이거나, 숫자가 아닌 값이 있으면 **입력 오류**(판정 아님, 거부). 출처 단계가 목록 밖이면 입력 오류.
- 경계 비교(V·온도 대 경계값)는 **정확한 비교**다(허용 오차 없음, 같은 숫자 판정은 R2 에서만 허용 오차 사용). 사례 생성기는 값을 문자열→Decimal 또는 정수 단위(mV·0.1 °C)로 만든다(부동소수 계산으로 경계값을 만들지 않음).
- 오라클은 판정과 함께 **이유 집합**(위반이 난 경계: supply_min·supply_max·abs_max·temp_min·temp_max, 판정 불가가 난 경계)을 돌려주고, 엔진과 **이유까지** 비교한다. R6 의 "절대 최대 초과가 권장 위반보다 심함"은 이유 집합에 abs_max 가 들어 있는지로 확인한다.

## 필드 확정 (R1~R5)
- **R1 단계 순서(높음→낮음)**: 데이터시트(사람 확인·위임 확인 포함) > 유통사 > 라이브러리. 필드의 확정 값은 값이 있는 가장 높은 단계에서 정한다. (라이브러리가 최하위라는 것은 "원문에 가까운 출처가 이긴다"의 연장이며 문서 근거 약함.)
- **R2 같은 단계 충돌**: 가장 높은 단계에 서로 다른 숫자가 둘 이상이면 그 필드는 **충돌**(판정 불가)이다. 낮은 단계 값으로 대신하지 않는다. 숫자가 같으면 충돌이 아니다. **같은 숫자(3판 변경 2026-11-15, 98 검토로 대칭화)**: 같은 단계 모든 값 중 (최대−최소) ≤ 1e-6 × max(1, 그 값들의 절대값 최대) 이면 같은 숫자(표기 차이 4.5 vs 4.50 흡수), 아니면 충돌. 순서와 무관하다(첫 값 기준은 [a,b=a+0.9t,c=a−0.9t] 순서에 따라 value/conflict 가 갈려 폐기). 같은 숫자로 묶인 값들의 확정 값은 **위험 방향으로 보수적인 값**: supply_min·temp_min → 최대값, supply_max·abs_max·temp_max → 최소값(순서 무관·fail-closed). 사람 확인과 위임 확인이 같은 단계 안에서 다른 숫자를 낼 때(열린 질문 4)도 같은 규칙. 척도 max(1,·)는 전압·온도 필드에 같은 식(엔진 정의와 같은지는 아래 노출 이력 안에서 확인; 온도 0 근처는 절대 허용 오차 1e-6). 근거: 엔진 REL_TOL 정의에 맞춤 — jung-f1 이 엔진 constraints.py 54행 근처를 읽은 뒤 정했으므로 오라클 독립성의 노출 이력이다(해당 줄만). 엔진은 첫 값 기준이므로 경계 근처에서 갈릴 수 있고, 갈리면 엔진 결함 후보로 3라운드가 칸으로 잡는다(허용 오차 안 두 값 × 경계에 걸친 V × 순서 두 가지; 차이가 정확히 t·1.000001t·0.999999t 사례). 이전 2판의 '정확한 같음'은 퍼저에서 ±1e-7 섭동이 위험한 통과 유형 112건(6만 중)을 만든 사양 차이였다.
- **R3 높은 단계 우선**: 낮은 단계 값이 높은 단계 값과 달라도 높은 단계 값이 이기며 충돌이 아니다(데이터시트≠유통사 → 데이터시트).
- **R4 없음**: 값 목록이 비면 그 필드는 **없음**이다. 필드가 없음이면 그 필드에 기대는 경계 판정은 **판정 불가**다(통과가 아님). 다른 필드로 위반이 확정되면 R9에 따라 위반이 이긴다.
- **R5 위임 확인과 abs_max**: 위임 확인 값은 데이터시트 단계 값으로 쓰되 결과에 경고 DELEGATED_CONFIRMATION 을 붙인다. abs_max_supply_v 는 **사람 확인 값만 인정**한다: 이 필드에 들어온 위임 확인 값은 사용하지 않고 목록에서 제외한 뒤 남은 값으로 R1~R3 을 적용한다(남은 값이 없으면 없음 → R4·R7·R9 로 판정 불가, 통과 불가). 입력 오류로 거부할지는 근거 약함이며 오라클은 거부가 아니라 제외로 처리한다. (98 중재 2026-11-15: 규칙 문장과 일치하는 쪽은 '판정 불가', '문장이 직접 정하지 않았고 취지는 안전 임계값은 위임 확인으로 통과 근거가 될 수 없음', 확신도 중간. 98 은 constraints.py 의 abs_max 관련 줄을 일부 본 적이 있는 한계.) 98 이 제안한 경고 DELEGATED_ABS_MAX_IGNORED 는 엔진에 없어 비교하지 않는다.

## 경계 판정 (R6~R8, 경계별로 푼다. 모든 비교는 경계 포함)
- **R6 전원**:
  - V < supply_min_v(확정 값 있음) → 위반. supply_min_v 가 없음/충돌 → 이 경계는 판정 불가.
  - V > supply_max_v(확정 값 있음) → 위반. supply_max_v 가 없음/충돌 → 이 경계는 판정 불가.
  - V > abs_max_supply_v(확정 값 있음) → **절대 최대 초과 위반**(권장 위반보다 심함). V = abs_max_supply_v 는 초과가 아니다. abs_max_supply_v 가 없음/충돌 → 이 경계는 **판정 불가**.
- **R7 절대 최대가 없음/충돌일 때**: 위 R6 에 따라 그 경계는 판정 불가다. 따라서 권장 안(V 가 supply_min_v..supply_max_v 안)인데 abs_max 가 없음/충돌이면 R9 에 의해 종합은 **판정 불가**이다(통과 아님). 위치가 '절대 최대 초과'인데 supply_max 가 확정이면 V > supply_max_v 로 위반이고(R6), supply_max 도 없음이면 판정 불가이며, 어느 쪽이든 통과는 아니다(명세 2 위험 칸 1 과 같음).
- **R8 온도(구간)**: 동작점 구간 [Ta_lo, Ta_hi]. Ta_lo < temp_min_c(확정 값 있음) → 위반. Ta_hi > temp_max_c(확정 값 있음) → 위반. 해당 경계 필드가 없음/충돌이면 그 경계는 판정 불가. 온도 '위치'(범위 미만·최저·안·최고·초과)는 부품 범위를 **벗어난 쪽 끝** 기준으로 정한다.

## 종합 (R9)
하나라도 위반이면 **위반**. 위반이 없고 판정 불가가 하나라도 있으면 **판정 불가**. 둘 다 없으면 **통과**(경고 가능). 한 필드의 없음이 다른 필드의 위반을 가리지 않는다(작업일지 11-14 그룹별 채점 근거).

## 열린 질문 (엔진을 보지 않고는 정해지지 않는 것)
1. 라이브러리 단계가 유통사 바로 아래 최하위인지(R1 의 가정, 문서 근거 약함, 기본값 최하위).
2. (닫음) 자동 추출 'extracted' 단계는 오라클 입력에 없다(명세 2 증거 상태 8가지에 없고 일지에 제약 판정에 연결하지 않음). 들어오면 입력 오류.
3. (닫음) 권장 안 + abs_max 없음 → 판정 불가(명세 2 성질 오라클 "값이 빠지면 통과가 되지 않는다", 일지 11-15 S1→S3 "안전하지만 판정 불가"). 서비스 동작으로 "통과+경고"를 원하면 그때만 사용자 결정 대상.
4. 사람 확인과 위임 확인이 같은 필드에서 다른 값을 낼 때: 충돌(판정 불가)로 둠. 사람 확인 우선인지는 문서 근거 없음.
5. abs_max 에 들어온 위임 확인 값의 결과가 "없음 취급"인지 "입력 오류 거부"인지(R5): 오라클은 "없음 취급, 값 무시"를 정답으로 한다. 엔진이 오류를 내면 어긋남으로 기록하고 이 문장의 근거(일지)로 판정한다.
(4 와 5 는 위 이유로 정답을 정했지만 근거가 약해 어긋남이 나오면 사용자 결정 대기 목록에 올린다.)

위험한 통과(오라클이 위반·판정 불가인데 엔진이 통과) 개수 0은 규칙이 아니라 **보고 기준**이며 명세 2 §6 에 있다.
