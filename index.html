① 로컬 실행 환경 준비

GitHub Pages는 공개 학습 화면입니다. 처음 한 번만 Ubuntu 터미널에서 ① 기본 세팅 명령을 실행하면, 그 뒤로는 이 페이지의 버튼으로 내 PC의 서비스 시작·업데이트를 실행할 수 있습니다(실행 전 Chrome 확인창). 이미 설치한 프로그램은 다시 설치하지 않습니다.

1처음 한 번: 기본 세팅소스 내려받기, 비밀번호 설정, 패키지·테스트, 서비스 등록, 모델 준비, 최종 상태 출력
2매일 로컬 서버 시작FastAPI와 LM Studio 상태 확인, 필요 시 시작. Elasticsearch는 상태만 확인
3로컬 서비스 접속127.0.0.1:8000에서 채팅과 PDF 관리 실행
① 처음 한 번: 기본 세팅 (다시 실행해도 안전)
[ -d ~/langchain_web/.git ] || git clone https://github.com/Yuul-Jung/langchain-lab.git ~/langchain_web; bash ~/langchain_web/scripts/setup-local.sh

미리 필요한 것: LM Studio(DeepSeek-R1-Distill-Qwen-14B, Qwen3-Embedding-4B 내려받기)와 Elasticsearch 9 설치. 세팅 스크립트가 빠진 항목과 조치 명령을 알려 주며, sudo는 자동으로 실행하지 않습니다.

버튼으로 내 PC에서 실행 (기본 세팅을 한 번 한 뒤부터)
▶ 로컬 서비스 시작 ⟳ 최신 버전으로 업데이트 ⚙ 기본 세팅 다시 실행

누르면 Chrome이 xdg-open 열기를 묻습니다. 허용하면 터미널 창이 열려 진행 상황을 보여 주고, 이 페이지가 아래 ③ 상태를 자동으로 다시 확인합니다. 버튼이 반응하지 않으면 위 ① 기본 세팅 명령을 터미널에서 한 번 실행하세요(실행기 등록). 실행기는 시작·업데이트·세팅 세 가지 동작만 받습니다.

평소 실행 (매번 이 명령 하나)
cd ~/langchain_web && bash scripts/start-local.sh
소스 업데이트 (GitHub에 새 버전이 올라왔을 때)
cd ~/langchain_web && bash scripts/update-local.sh
② 로컬 AI 채팅 열기 PDF 문서 관리자 연결 진단 결과
③ 로컬 프로그램 상태 확인

내 PC의 127.0.0.1:8000/api/status에 상태만 묻습니다(읽기 전용). Chrome이 로컬 네트워크 기기 접근 허용을 물으면 허용하세요. 채팅·문서 내용은 이 페이지로 전송되지 않습니다.

    로컬 주소가 열리지 않으면 먼저 실행 명령의 진단 결과를 확인하세요. 외부 GitHub Pages에서는 운영체제 보안상 로컬 서비스를 직접 시작할 수 없습니다. 상태 확인(③)은 서비스가 실행 중인 PC의 브라우저에서만 동작합니다.
