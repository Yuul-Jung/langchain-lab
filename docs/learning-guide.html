05. LangChain과 LM Studio 첫 연결

목표 — LM Studio 모델 목록 읽기 → DeepSeek 모델 지정 → LangChain을 통한 한국어 답변 확인.
from langchain_openai import ChatOpenAI

# LM Studio에서 실행하는 생성 모델 호출
llm = ChatOpenAI(
    model="deepseek-r1-distill-qwen-14b",
    base_url="http://127.0.0.1:1234/v1",
    api_key="lm-studio",
    temperature=0,
    use_responses_api=False
)

# 한국어 시스템 프롬프트와 사용자 질문
response = llm.invoke([
    ("system", "모든 최종 답변은 한국어로 작성하세요."),
    ("human", "LangChain이 무엇인지 설명해줘.")
])
print(response.content)
실제 검증: DeepSeek 모델을 통해 한국어 답변이 출력됐다. 하지만 일부 후속 답변에는 중국어·영어 혼용이 나타나 생성 모델 품질 개선이 필요하다.

06. Elasticsearch 9.5.6 실행 및 HTTPS 연결

# 서버 실행
sudo systemctl start elasticsearch

# 재부팅 시 서비스 자동 시작 등록
sudo systemctl enable elasticsearch

# 서비스 실행 상태 확인
systemctl is-active elasticsearch

검증 결과 — active 상태와 Elasticsearch 버전 9.5.6을 확인했다.

CA 인증서 접근 오류 해결

# Elasticsearch가 생성한 CA 인증서를 사용자 전용 위치에 복사
mkdir -p ~/.config/elasticsearch
sudo cp /etc/elasticsearch/certs/http_ca.crt \
  ~/.config/elasticsearch/http_ca.crt
sudo chown "$USER:$USER" \
  ~/.config/elasticsearch/http_ca.crt
chmod 600 ~/.config/elasticsearch/http_ca.crt

# HTTPS 인증 테스트 (비밀번호는 프롬프트에서 입력)
curl --cacert ~/.config/elasticsearch/http_ca.crt \
  -u elastic https://localhost:9200

원본 CA 인증서에 읽기 권한이 없어 curl: (77)이 발생했다. 인증서를 복사한 후에는 비밀번호 오류 401이 별도로 발생했으며, 관리자 비밀번호 재설정 후 서버 정보를 정상 수신했다.

보안 기준: elastic은 관리자 계정이다. 개인 실습 이후에는 읽기·쓰기 권한을 분리한 서비스 계정 또는 API 키로 전환해야 한다. TLS 인증서 검증을 끄는 -k나 verify_certs=False를 상시 해결책으로 사용하지 않는다.

Python 패키지 버전 충돌 해결

langchain-elasticsearch 1.0.0은 당시 elasticsearch 8.x 클라이언트를 요구했으므로, Elasticsearch 서버 9.5.6과 맞추기 위해 Python elasticsearch 9.x 클라이언트를 직접 사용했다. LangChain은 생성 모델 호출과 질문 구성에 사용한다.

비ASCII 비밀번호 인코딩

# 비ASCII 문자 포함 비밀번호를 UTF-8 Basic 인증 헤더로 변환
raw = f"{ES_USER}:{password}".encode("utf-8")
authorization = "Basic " + base64.b64encode(raw).decode("ascii")

es = Elasticsearch(
    "https://localhost:9200",
    ca_certs=CA_CERT,
    headers={"Authorization": authorization}
)

초기 UnicodeEncodeError는 클라이언트 인증 문자열의 ASCII 처리 문제였고, 위 방식으로 수정한 뒤 벡터 검색 성공 결과를 얻었다.

10. systemd 자동 실행

반복해서 터미널에서 서버를 실행하면 포트 8000 중복 점유가 발생한다. 따라서 사용자용 systemd 서비스로 자동 시작을 설정한다.

# 프로젝트 업데이트
cd ~/langchain_web
git pull origin main
source .venv/bin/activate
python -m pip install -r requirements.txt

# 최초 1회: 비밀번호 로컬 .env 설정 (GitHub 업로드 금지)
python scripts/configure-elasticsearch.py

# 최초 1회: 사용자 서비스 등록
bash scripts/install-service.sh

# 이미 수동 실행 중인 uvicorn은 기존 터미널에서 Ctrl+C로 종료
# 등록된 서비스 시작
systemctl --user start langchain-lab

# 실행 상태 및 로그 조회
systemctl --user status langchain-lab --no-pager
journalctl --user -u langchain-lab -n 40 --no-pager
운영 범위: 사용자 systemd 서비스는 일반적으로 사용자 로그인 시 동작한다. LM Studio 자체의 로그인 후 서버 시작 설정 및 모델 자동 로딩도 별도로 확인해야 하며, 컴퓨터 전원 OFF 상태에서는 로컬 LLM을 제공할 수 없다.
