00학습 개요 — 전체 기술 위치

로컬 RAG(Retrieval-Augmented Generation, 검색 증강 생성)는 단일 언어 모델이 모든 것을 기억하도록 만들지 않는다. 질문을 검색하고, 관련 문서를 찾아, 그 문서의 내용으로 답변을 생성하는 시스템이다. 모델을 실행하는 엔진·검색 데이터베이스·웹 서버는 역할이 다르다.

기술무엇을 하는가무엇을 하지 않는가
LM StudioAI 모델을 메모리에 올리고 API로 실행기술 문서 검색 데이터베이스가 아님
LangChain프롬프트·모델 호출·검색 결과 연결모델을 직접 학습시키는 실행 엔진이 아님
Elasticsearch문서 저장·키워드 및 벡터 검색자연어 답변 생성 모델이 아님
FastAPI웹 질문·응답 및 관리 API검색 품질을 자동 보장하지 않음
이 과정의 실제 검증 범위: LangChain 모델 호출, Qwen3 2,560차원 벡터 생성, Elasticsearch 문장 3개 검색, 로컬 HTML 일반 채팅. PDF 자동 등록·실제 문서 출처·완전한 운영 자동화는 후속 과제이다.

01전체 실습 흐름

response = llm.invoke([

코드 풀이 — HTTPS 인증서와 관리자 계정이 모두 통과해야 검색할 수 있다

처음에는 인증서 파일을 읽지 못해 curl (77) 오류가 발생했다. 인증서를 사용자 폴더로 안전하게 복사한 뒤 401 비밀번호 오류를 별도로 해결하여 서버 정보를 정상 확인했다.

위 JSON은 실제 출력의 주요 필드만 발췌한 것이다. 개인정보를 포함할 수 있는 호스트 이름과 클러스터 ID는 배포 예제에서 제외한다.

실무용 서비스에서는 관리자 elastic 계정을 상시 사용하지 않는다. 최소 권한 API 키 또는 서비스 계정을 적용하고 비밀번호를 GitHub에 올리지 않는다.

07벡터 인덱스 생성과 kNN 검색

CODE · test_elasticsearch_vector.py 핵심 흐름
# 질문과 문서 모두 동일한 임베딩 모델로 벡터화
query_vector = embed("모터 과열 시 확인할 사항은?")

# Elasticsearch에서 가장 가까운 문서 3건 검색
result = es.search(
    index="langchain_embedding_lab",
    size=3,
    knn={
        "field": "embedding",
        "query_vector": query_vector,
        "k": 3,
        "num_candidates": 10,
    },
    source=["text"],
)
OUTPUT · 실제 관찰 또는 확인 기준
질문: 모터 과열 시 확인할 사항은?

2. 점수 0.8146 | 모터 온도가 높아질 때 보호 회로가 동작한다.

코드 풀이 — 키워드가 완전히 동일하지 않아도 관련 문장이 우선 검색된다

num_candidates

HTML은 입력을 받고 결과를 표시하지만 Python 로직을 실행할 수 없다. FastAPI가 HTTP 요청을 받아 LangChain과 Elasticsearch 코드를 호출한다. 현재는 로컬 화면을 FastAPI에서 함께 제공하므로 GitHub Pages의 브라우저 보안 제약을 우회한다.

코드의 ...는 설명용 생략 표시다. 실행 가능한 전체 코드는 저장소 app.py를 기준으로 확인한다.

코드 풀이 — 검색 근거를 생성 모델에 전달하고 화면에도 반환한다

현재 웹 화면에서 Elasticsearch가 ‘연결되지 않음’으로 표시된 기록이 있다. Python의 독립 벡터 검색은 성공했지만 웹 RAG 전체가 정상 동작한다고 확정할 수 없다.

journalctl

13확장 구조: PDF·데이터시트 전문 RAG

STM32 데이터시트처럼 정확한 핀명·전압·레지스터 주소가 중요한 자료는 벡터 유사도만으로 결론을 확정하지 않는다. 키워드 정확 일치 검색, 문서 버전 확인, 물리적·전기적 규칙 검증을 함께 사용한다.

위 구조는 후속 설계 목표다. 현재 실습에 PDF 자동 업로드나 하이브리드 검색이 이미 구현되어 있다는 뜻이 아니다.

14핵심 정리

현 단계에서 완료된 것은 모델 호출·문장 벡터화·Elasticsearch 벡터 검색의 핵심 요소이다. 이를 상용 수준의 기술 문서 검색 시스템으로 만드는 과정에는 안정적인 웹 RAG 연결, 문서 인제스트, 출처 메타데이터, 검색 품질 검증이 더 필요하다.

  • LM Studio: 로컬 모델 실행 서버
  • DeepSeek: 검색 결과를 바탕으로 자연어 답변 작성
  • Qwen3-Embedding-4B: 문장과 질문을 같은 벡터 공간으로 변환
  • Elasticsearch: 관련 문서를 검색하는 데이터베이스
  • LangChain + FastAPI: 처리 흐름과 웹 통신 연결
  • GitHub: 검증된 코드와 교재를 버전 관리하는 공간

다음 실습에서는 웹 RAG 연결 문제를 해결한 후 실제 기술 PDF를 인덱싱하고, 출처가 있는 질의응답을 완성한다.
