00과제 개요와 설계 원칙

제1장에서 LM Studio·LangChain·Elasticsearch 연동과 기본 벡터 검색을 구성했다. 제2장에서는 로컬 자료를 업로드하여 원본 구조 보존 → 내용 분류 → 선수학습 제안 → 지식 관계 생성 → Elasticsearch 등록 과정을 구현한다.

기본 원칙 — 원본 사실과 AI 추론은 별도 필드로 저장하고, AI가 제안한 분류·학습 경로는 승인 전까지 proposed(검토 대기)로 표시한다. 제1장 벡터 실습 인덱스는 수정하지 않는다.
구분주요 필드보존·검증 기준
원본source_order, page, title파일 추출 결과, 임의 재정렬 금지
분류topic, difficulty, concepts분석 방식·승인 상태 기록
관계from, to, type원본 관계와 추론 관계 구분
검색text, embedding, document_id별도 전용 인덱스에 저장

02원본 업로드와 보안 검사

CODE · document_api.py: 업로드 요청 일부
@router.post("/upload")
async def upload_document(
    file: UploadFile = File(...),
    use_ai: bool = Form(True),
    index: bool = Form(True),
):
    body = await file.read(MAX_BYTES + 1)
    if len(body) > MAX_BYTES:
        raise HTTPException(status_code=413, detail="파일은 최대 8MB")
    return ingest_file(file.filename or "", body,
                       use_ai=use_ai, index=index)
OUTPUT · 예시 / 확인 기준
[예시 응답]
{"duplicate": false,
 "document": {"document_id": "…",
              "index_status": "indexed"}}

코드 풀이 — 업로드 API는 파일을 제한 크기 안에서 읽는다

서버는 파일명을 경로로 사용하지 않고 UUID 기반 로컬 이름으로 저장한다. 중복 검사는 SHA-256 해시를 사용한다. 실제 코드는 예외 처리와 상태 복구가 추가되어 있으므로 document_api.py 전체를 참고한다.

업로드 화면은 127.0.0.1 로컬 개발 환경에서만 운영한다. 외부 네트워크에 노출하려면 인증·요청 제한·파일 검사·접근제어를 반드시 추가한다. 또한 8MB 크기 제한은 PDF 내부 압축 해제 후 메모리 사용량의 안전성을 보장하지 않는다.

sections = extract_sections(stored)

OUTPUT · 예시 / 확인 기준
[예시 출력 — Markdown 문서]

코드 풀이 — 원본 순서와 장·절의 상위 관계를 저장한다

source_order는 실제 추출 순서이며, parent_id는 H1/H2 등 제목 계층에서 계산한다. PDF는 우선 페이지 단위로 구조를 추출하므로 복잡한 목차나 그림은 별도 개선이 필요하다.

04텍스트 분할과 벡터 처리

CODE · document_pipeline.py: 청크 생성
sections = extract_sections(stored)
chunks = make_chunks(sections)
for item in chunks[:3]:
    print(item["chunk_id"], item["section_id"],
          len(item["text"]), item["page"])
OUTPUT · 예시 / 확인 기준
[예시 출력]
s0001_c001 s0001 1150 None
s0001_c002 s0001 1150 None
s0002_c001 s0002 420 None

코드 풀이 — 길이가 긴 절을 검색에 적절한 단위로 나눈다

청크마다 section_id와 원본 page를 보존한다. 중첩 길이는 서로 인접한 문장 사이의 검색 맥락을 유지하기 위한 것이다. 청크 개수는 최대 160개로 제한해 과도한 임베딩 요청을 막는다.

코드 풀이 — 원문에서 찾은 사실과 분류 모델의 판단을 구분한다

로컬 LLM을 호출하지만 추론 결과가 JSON 규칙을 따르지 않거나 서버 연결에 실패하면 키워드 기반 분류로 전환한다. 모델은 임의의 외부 URL에 전송하지 않고 지정된 로컬 LM Studio 주소를 사용한다. 주제·난이도는 원본에 명시된 사실이 아니라 검토가 필요한 분석 결과다.

06선수학습 관계와 지식 그래프 생성

관계의미근거
precedes원문에서 먼저 나타남원본 순서
contains상위 장이 하위 절을 포함원본 제목 계층
prerequisite선수학습 필요 제안사전 정의 규칙
related공통 개념 존재 제안제목 내 공통 기술 용어
CODE · document_pipeline.py: 관계 생성
edges = propose_relations(sections, classification["concepts"])
for edge in edges:
    print(edge["from"], "->", edge["to"],
          edge["type"], edge["provenance"])
OUTPUT · 예시 / 확인 기준
[예시 출력]
s0001 -> s0002 precedes source_extracted
s0002 -> s0003 precedes source_extracted
s0001 -> s0002 prerequisite rule_inferred
s0002 -> s0003 prerequisite rule_inferred

코드 풀이 — 원본 관계와 추론 관계를 한 데이터에 섞지 않는다

원문 순서는 추출한 사실이지만, 교육상 어떤 개념이 먼저 필요한지는 도메인 규칙에서 제안한 관계다. rule_inferred는 반드시 검토 상태로 보존한다. 초기 버전은 제목 키워드에 의존하므로 의미가 다른 동형 용어와 동일 개념의 다른 표현을 놓칠 수 있다.

코드 풀이 — 선수학습 조건으로 위상 정렬을 수행한다

위상 정렬은 먼저 배워야 하는 항목을 앞에 배치한다. 우선순위가 같은 경우 원본 순서를 유지한다. 순환 관계가 감지되면 원본 순서를 유지하며 경고를 표시한다. 승인 전에는 제안으로만 취급한다.

08Elasticsearch 검색 등록과 기존 인덱스 보호

CODE · document_pipeline.py: 등록 핵심
es = es_client()
_ensure_index(es)  # 신규 문서 인덱스의 매핑 확인
for chunk in chunks:
    vector = embed_query(chunk["text"])
    es.index(
        index=DOCUMENT_INDEX,
        id=meta["document_id"] + "_" + chunk["chunk_id"],
        document={**chunk, "embedding": vector,
                  "document_id": meta["document_id"]}
    )
OUTPUT · 예시 / 확인 기준
[확인 기준]
- 인덱스명: langchain_documents_v1
- embedding 매핑: dense_vector, 2560 dims
- 등록 후 index_status: indexed

코드 풀이 — 기존 실습 인덱스를 변경하지 않고 문서별 고유 ID로 등록한다

실제 구현은 _index_chunks()에 있으며 문서 제목·파일명·주제·등록일도 함께 저장한다. 등록 실패 시 가능한 범위에서 해당 문서의 청크만 정리하고, 카탈로그에는 실패 상태를 남겨 재시도할 수 있게 한다.

현재 버전의 롤백은 Elasticsearch 요청이 장기간 실패하거나 일부 응답이 유실되는 상황에서 완전한 트랜잭션을 보장하지는 않는다. 실무 운영에는 작업 큐·재시도·배치 처리·복구 검증이 추가로 필요하다.

11오류 해결과 제한 사항

문제원인조치
업로드 처리 실패형식·용량·텍스트 추출 오류8MB 제한과 지원 확장자 확인
스캔 PDF 빈 텍스트이미지 PDFOCR(광학 문자 인식) 별도 단계 추가
벡터 등록 실패LM Studio·ES 접속 불가서버 상태·CA 인증서·비밀번호 확인
분류가 미분류모델 실패·키워드 부족분류 제안을 확인하고 규칙 확장
학습 순서 부정확제한된 선수학습 규칙관계 근거 확인·규칙 검토
검색 점수 높지만 오답의미 유사도 ≠ 사실 정확성정확 일치 검색·출처 검증 확장
로컬 PC 전용 개발 기능이다. 보안을 위한 전체 사용자 인증, 바이러스 검사, 대용량 파일 작업 큐, PDF OCR, 문서별 접근 권한은 후속 버전에서 다룬다.

12핵심 정리 · 다음 단계

제2장 실습에서 새롭게 얻는 결과는 문서 원본·분류 제안·학습 순서·지식 관계·검색 청크를 서로 분리한 구조화 자료다. 원문과 분석 결과가 독립되어 있어 자동 교재 재편성에 활용할 수 있다.

  • 원본 순서와 학습 순서를 구분하여 저장한다.
  • LLM 분석은 원본 사실이 아니라 검토 대기 제안으로 취급한다.
  • 기존 제1장 실습 인덱스를 덮어쓰지 않는다.
  • 문서 등록 오류가 발생하면 상태를 남기고 원인을 점검한다.
  • 실제 기술문서 기반 RAG는 검증 자료와 정확도 평가를 추가해 완성한다.
